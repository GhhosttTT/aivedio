# 12GB 显存量化图像编辑部署

## 结论

RTX 3060/4070 12GB 可以运行量化版 Flux Kontext 或 Qwen Image Edit。模型、文本编码器、VAE 和运行缓存无法全部常驻 12GB 显存，因此必须使用 ComfyUI `--lowvram`、量化权重和 CPU offload。系统只在候选关键帧通过初选后加载编辑模型。

推荐顺序：

1. Flux Kontext Q4_K_M + T5XXL FP8：默认语义修复引擎。
2. Qwen Image Edit Q3_K_M + Qwen2.5-VL Q4：高价值镜头的慢速修复。
3. SDXL 局部修复：眼睛、皮肤、手指等小范围缺陷。

Qwen Image Edit Q4 主模型约 12GB，留给文本编码器、VAE 和缓存的空间不足。12GB 显卡优先使用 Q3；Q4 需要更积极的 CPU offload，速度和稳定性取决于系统内存、页面文件和 ComfyUI 版本。

## 依赖

- 最新版 ComfyUI。
- `city96/ComfyUI-GGUF`。
- Flux Kontext 所需的原生 ComfyUI 节点。
- Qwen Image Edit 所需的 `TextEncodeQwenImageEdit`、`ModelSamplingAuraFlow`、`CFGNorm` 节点。
- 建议至少 32GB 系统内存；64GB 更稳。
- SSD 页面文件建议保留 32GB 以上空间。

## 模型目录

Flux Kontext 示例文件：

```text
ComfyUI/models/unet/flux1-kontext-dev-Q4_K_M.gguf
ComfyUI/models/text_encoders/clip_l.safetensors
ComfyUI/models/text_encoders/t5xxl_fp8_e4m3fn_scaled.safetensors
ComfyUI/models/vae/ae.safetensors
```

Qwen Image Edit 示例文件：

```text
ComfyUI/models/unet/Qwen_Image_Edit-Q3_K_M.gguf
ComfyUI/models/text_encoders/qwen_2.5_vl_7b_instruct-Q4_K_M.gguf
ComfyUI/models/text_encoders/Qwen2.5-VL-7B-Instruct-mmproj-BF16.gguf
ComfyUI/models/vae/qwen_image_vae.safetensors
```

GGUF 文本编码器需要配套 mmproj。具体文件名以实际下载模型和 ComfyUI `/object_info` 返回值为准，工作流中的名称必须完全一致。

## aivedio 配置

```dotenv
COMFYUI_VRAM_MODE=lowvram
COMFYUI_IMAGE_EDIT_ENABLED=true
COMFYUI_IMAGE_EDIT_ENGINE_REGISTRY_PATH=./configs/local_image_edit_engine_registry.12gb.example.json
COMFYUI_IMAGE_EDIT_ENGINE=auto
LOCAL_IMAGE_EDIT_VRAM_BUDGET_GB=12
LOCAL_IMAGE_EDIT_ALLOW_CPU_OFFLOAD=true
```

默认路由会优先选择 Flux Kontext。需要强制 Qwen 时设置：

```dotenv
COMFYUI_IMAGE_EDIT_ENGINE=qwen_image_edit_q3
```

## 生产行为

1. SDXL 负责候选关键帧和构图搜索。
2. 审核通过后生成局部修复计划。
3. 身份、服装、道具和错误文字进入语义编辑引擎。
4. 面部、眼睛、皮肤、手指进入 SDXL 局部修复。
5. 每次编辑保存实际 ComfyUI API 工作流，便于复现和排查。
6. 模型或节点缺失会在 `/object_info` 预检阶段失败，不会静默改用错误模型。

## 尚需实机验证

- 首次加载耗时和单张编辑耗时。
- Q3 与 Q4 的身份保持差异。
- 768x1344 输入在不同驱动和 CUDA 版本下的峰值显存。
- CPU offload 对系统内存和页面文件的峰值占用。
- Flux 与 Qwen 对服装、道具、多人物镜头的成功率。

代码测试只能证明路由、工作流绑定、失败处理和报告逻辑。最终画质必须用本机模型权重生成代表性镜头后进行人工审核。
